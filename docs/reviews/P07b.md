## Reviewed scope

The immutable approval type validates the exact 14 top-level fields and all nested field sets against the accepted P06a profile. It bounds original bytes before parsing, retains decoded-duplicate rejection and integer lexical restrictions, and checks IDs, canonical base64url, checked positive TTL, fixed versions/profile/action/host, branch grammar and display label grammar. Repository IDs remain decimal strings, including valid values beyond `u64`.

Maintained JCS serialization runs only after schema checks. Canonical output is independently bounded. The separate canonical-input method requires original bytes to match canonical bytes; it does not turn a rewritten artifact into valid signature input. No public mutable constructor bypasses raw-input checks. Errors omit source values and upstream diagnostics.

The independently generated current-profile approval string supplies the literal byte oracle. Tests cover every missing and unknown field, wrong-type matrices, field bounds, noncanonical base64url padding/trailing bits, timestamp underflow/overflow and TTL boundaries, all frozen branch exclusions, labels, formatting-equivalent inputs, canonical reparse stability and raw 8,192-byte limits before normalization. They do not fabricate an unknown padding field to claim a valid maximum-sized canonical payload.

Enrollment, current time, trusted display/resource resolution, signature verification and execution authorization are deliberately absent. Parsing success is schema validity only. No native provider or live operation was added.
