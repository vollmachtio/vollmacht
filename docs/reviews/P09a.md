# P09a signed client-data syntax review

Implementation author: `contract_revision`. Independent test author: `p06_acceptance_audit`. Independent adversarial reviewer: `adversarial_p02`.

Disposition: no blocking findings. The separate client-data visitor adopts the accepted Unicode and extension policy rather than the narrower application JSON profile. It checks strict UTF-8, one object root, decoded duplicate member names at every nested object, valid surrogate pairs and finite numeric conversion. The original input is capped at 12,288 bytes; objects and arrays count toward the sixteen-container limit, including the root.

The immutable borrowed wrapper exposes only original bytes, with redacted Debug and errors. No canonicalization or semantic map is returned. Unicode, whitespace, escapes and supported numeric spelling remain untouched for later signature verification. Empty objects and semantically invalid WebAuthn fields deliberately pass the syntax-only boundary.
