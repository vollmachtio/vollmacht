## Reviewed boundaries

Input size is checked before parsing or allocation, with an absolute 65,536-byte ceiling and a validated smaller trusted cap. Strict UTF-8, BOM rejection and complete input consumption surround maintained serde parsing. Decoded object names are checked for duplicates before insertion. The root counts as object depth one; the ninth object rejects before allocating its map.

Only printable ASCII strings and keys, objects and unsigned integers through 9,007,199,254,740,991 are accepted. Signed, floating, boolean, null and sequence visitors remain absent. Tests exercise negative zero, exponent/fraction spellings, leading zeros, overflow, escaped-equivalent duplicate names, malformed UTF-8/surrogates, decoded controls and exact size/depth limits under the pinned dependency graph.

The public output has no constructor, mutable accessor or deserialization bypass. Its borrowed fields establish syntax only, not exact schema, canonicality, evidence, trust or authorization. Errors omit source bytes and upstream diagnostics. This parser is explicitly unsuitable for signed WebAuthn client data.

The new `trusted_core` inventory role is not an exclusion or qualification claim. Source completeness and measurement validation remain unchanged. Core files are honestly classified as unmeasured; existing tests and checks are retained. Cargo adds only the local package, without dependency-version changes.
