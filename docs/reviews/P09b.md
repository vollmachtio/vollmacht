# P09b assertion-helper syntax enforcement review

Implementation author: `contract_revision`. Independent test author: `p06_acceptance_audit`. Independent adversarial reviewer: `adversarial_p02`.

Disposition: no blocking findings. The experimental version 1 assertion helper now validates signed client-data syntax before decoding security fields. Original encoded evidence reaches SimpleWebAuthn unchanged. Canonical base64url and encoded-size enforcement remain the existing `parseRequest` transport prerequisite; direct `verifyRequest` is not a standalone untrusted transport API.

The adapter pins `jsonc-parser` 3.3.1 and uses its visitor rather than a new tokenizer or permissive value builder. Review inspected installed source and confirmed callback exceptions propagate. Every parser error/comment rejects immediately, depth is bounded before descent, decoded names are tracked per object, and malformed surrogates/nonfinite numbers reject. Unicode extensions remain permitted under the accepted policy. The [tagged upstream implementation](https://github.com/microsoft/node-jsonc-parser/blob/v3.3.1/src/impl/parser.ts) is the parser reference, not a claim that its defaults implement Vollmacht policy.

## Validation and limits

- Independent reviewer: nine syntax groups, six signed regressions, 28 cross-runtime tests, five lock-policy controls and 132-source inventory passed. Additional numeric edge cases agreed with Rust.
- Coordinator: complete Node `npm test`, pinned-runtime `python3 scripts/check.py`, 28 cross-runtime checks and 23 helper end-to-end tests passed. `npm audit` for runtime dependencies reported zero vulnerabilities.
- Previously permissive signed ambiguity cases remain tested with explicit rejection expectations. Historical observation tables are retained and clearly separated from current helper behavior. Legitimate whitespace/Unicode signatures remain positive controls; reserialization without resigning fails.
- Lock delta adds only jsonc-parser 3.3.1, from the npm registry with SHA-512 integrity, MIT license and no runtime dependencies or lifecycle changes. Installation disabled lifecycle scripts. Existing dependency versions are unchanged.
- No tests or coverage requirements were weakened. New source files remain explicitly unmeasured. Initial sandbox loopback denial was resolved by running the unchanged HTTP tests with loopback permission, not suppression.
- No native authenticator, Keychain or live GitHub operation occurred. This is experimental assertion-helper hardening, not production packaging, registration integration or complete controller-side enforcement.
- Exact integrated-head mandatory CI remains required before protected merge.
