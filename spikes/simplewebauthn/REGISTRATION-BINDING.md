# Registration identity-binding assessment

Test-only characterization, 2026-10-07, for the pinned SimpleWebAuthn server 14.0.3. This does not fix the experimental Session, implement production enrollment or accept P06. All credentials, flags and signatures are synthetic software fixtures; no person or platform authenticator participates.

`registration-binding.test.mjs` verifies that matching browser `id` and `rawId` return the fixture's credential ID and public key from authenticator data. Disagreement between the two browser IDs rejects. However, changing both browser IDs together while retaining a different ID in authenticator data **still verifies in the current library**. Its returned credential ID is the extracted authenticator-data value, not the changed browser value. The test explicitly detects that disagreement; no deployed check is added here.

The current experimental Session stores the returned credential, rather than trusting the browser ID as the registry key. Nevertheless, the [proposed enrollment contract](../../docs/architecture/enrollment.md) requires all three IDs to agree before enrollment. Production enforcement and strict registration transport/ambiguity handling remain future work. Library acceptance alone must not be presented as satisfying that contract.

The fixture's `none` attestation has an empty attestation statement, so successful registration here supplies no attestation signature proving possession of the candidate private key or authenticator provenance. A fresh activation assertion verifies with the returned credential's key. A separate software key's genuinely valid signature, relabeled with the candidate credential ID, fails verification against the candidate key. Independent Node crypto checks distinguish that wrong-key case from a malformed signature. This illustrates the proposed activation check; it does not implement candidate-only pending state, protected administration or atomic registry commit.

Run `node spikes/simplewebauthn/registration-binding.test.mjs` with pinned Node 24.21.0. Repository test discovery is explicit: integration must add this file to the npm test command and source inventory. No dependency, live credential, native operation or fixture private key is persisted. Enrollment timing, cancellation, replay, unknown/duplicate signed data, current registry status and protected bootstrap remain separate gates.
