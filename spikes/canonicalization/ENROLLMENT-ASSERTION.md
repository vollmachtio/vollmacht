# Synthetic enrollment assertion linkage

Assessment only, 2026-10-06. `spikes/simplewebauthn/enrollment-assertion.test.mjs` links software-generated WebAuthn assertion bytes to the exact reviewed [candidate enrollment](ENROLLMENT.md) proposal A digest. It changes no existing vector, helper, browser or production API. No real passkey, user, Touch ID or native operation participates.

The test recomputes SHA-256 over the recorded administrative domain, its one zero byte and A's literal canonical bytes. It checks the committed hex/base64url digest and uses it as the expected assertion challenge. The existing synthetic authenticator signs original client data and authenticator data with a fresh software P-256 key. Test setup deliberately associates A's credential ID with that synthetic public key in a separate expected credential record. This is not evidence of registration, protected registry provenance or possession of any operational credential. Flags claiming UP/UV are synthetic bits, not observed human verification.

The unchanged strict helper request decoder and maintained SimpleWebAuthn verifier check the original assertion. Separate Node crypto checks establish that wrong-challenge, wrong-origin, wrong-RP and missing-UV examples have intact signatures even though trusted verification rejects them. Replacing proposal identities, revisions or nonce changes the expected digest and rejects the unchanged signed evidence. Wrong administrative domain separators and a mandate domain also reject. Equivalent client-data reserialization without resigning fails, while the retained original remains valid.

Verification twice against the original counter context intentionally succeeds. This highlights the helper's boundary: it does not consume an administrative capability, persist counters, enroll an agent or prevent replay. No expiry, cancellation, current registry status, atomic commit, bootstrap isolation or protected storage claim follows. The separate possession-proof vectors and this test are not an integrated two-stage enrollment state machine. Signed-client-data ambiguity gating and private-pipe process orchestration remain separate assessments; this test calls the verification function directly.

Run the test directly with the pinned Node 24.21.0 runtime: `node spikes/simplewebauthn/enrollment-assertion.test.mjs`. The package's test command enumerates files explicitly, so repository integration must append this file to that command and account for it in the source inventory. Nothing is discovered merely because its name ends in `.test.mjs`. The fixture uses generated in-memory keys; no private key, raw assertion or capability is written to disk.

This evidence supports further P06 review, not acceptance or production P07 implementation. Physical enrollment UX and P04b hardware/isolation gates remain open.
