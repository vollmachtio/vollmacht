# Canonical serialization feasibility spike

Assessment only. This isolated Cargo workspace evaluates `serde_jcs` 0.2.0 serialization. It exports no production parser, mandate schema, authorization API or JOSE implementation. Nothing here freezes P06 or completes P07.

Direct dependencies are pinned: serde_jcs 0.2.0, serde_json 1.0.151, OpenSSL 0.10.81 and base64 0.21.7. The last three match existing repository pins. serde_jcs 0.2.0 was released March 25, 2026; its declared normal dependencies are ryu-js, serde and serde_json. Exact resolved dependencies require the standalone lockfile and fresh advisory/license review before merge. No advisory-clean claim follows merely from choosing a recent version. [Primary crate metadata](https://docs.rs/crate/serde_jcs/0.2.0)

## Evidence

The eight tests compare serialization with hand-written literal bytes for nested ASCII property sorting, string escaping and exactly representable nonnegative integer fixtures. A reverse-ordered map exercises serializer sorting without relying on serde_json's already-sorted map. OpenSSL computes a domain-separated SHA-256 fixture and the RFC 7638 public EC JWK thumbprint candidate. Digest expectations were independently calculated with Node crypto over those literal constructions, not generated by serde_jcs.

The domain is `vollmacht:experimental:canonicalization-spike:v1` followed by one NUL byte. It is deliberately not a production mandate domain. The public JWK uses the standard P-256 generator point, not a user's key. Thumbprint hashing uses only required public members and no Vollmacht domain. Tests do not validate EC membership or establish key enrollment.

Two negative demonstrations intentionally show that ordinary serde_json map parsing collapses duplicate keys (including escaped equivalent names) and that canonicalization erases distinctions among integer, fractional and exponent spellings. These passing tests expose why this pipeline must NOT accept untrusted mandate JSON. A separately reviewed bounded parser must reject duplicate members and forbidden lexical forms before map construction or canonicalization.

This fixture set covers a restricted ASCII/integer subset, not full RFC 8785 conformance. It does not assess all Unicode sorting, floating-point behavior, recursion bounds or resource exhaustion. There is no custom canonicalizer. [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785), [RFC 7638](https://www.rfc-editor.org/rfc/rfc7638)

## Run

From repository root, run `python3 scripts/check-canonicalization.py` for formatting, strict Clippy and locked tests. This isolated workspace is outside the main Cargo workspace; `scripts/check.py` invokes its checks explicitly on both CI platforms. Its target output is ignored locally. `python3 scripts/dependencies.py` checks both dependency graphs, using the repository-root `deny.toml` for this manifest rather than an implicit default policy.

## Library tradeoff and remaining gate

serde_jcs supplies a small serializer surface; duplicate detection, accepted lexical forms and bounded input handling remain our separate validation responsibilities. Production selection depends on resolved dependency review and more independent vectors, not these tests alone.

Installed 0.2.0 source sorts object keys using UTF-16 and converts integer values through f64 before formatting. The tested integer boundary is therefore deliberate; do not infer support for arbitrary-width integers. Its `to_string` convenience API contains an unsafe UTF-8 conversion; this spike calls `to_vec` instead. Dependency code is outside our crate's unsafe-code prohibition. This source inspection is not a safety certification. [Pinned serializer source](https://docs.rs/crate/serde_jcs/0.2.0/source/src/lib.rs)

The parallel library review identified josekit 0.10.3 as an OpenSSL-based candidate with a custom `JwsSigner` interface, but its broader JWE-related dependency surface and older release require assessment. No JOSE library is selected here. A narrow custom JWS wrapper would not automatically satisfy the plan's maintained-JOSE-library gate. [josekit metadata and API](https://docs.rs/josekit/0.10.3/josekit/)
