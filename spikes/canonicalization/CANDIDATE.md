# Provisional full-payload vectors

Assessment snapshot: 2026-10-03, following the proposed [mandate contract](../../docs/architecture/mandate-contract.md). These fixtures do not freeze P06, implement a parser, or authorize P07. The candidate's `v1` domains are exercised provisionally, not published as a stable protocol. A later contract change must explicitly revise these fixtures and their independent expectations.

`fixtures/candidate-payload.json` contains every candidate payload field. IDs are repeated test digits, nonce is 32 zero bytes, credential ID decodes to `01 02 03 04`, and agent thumbprint is the public P-256 generator fixture from `tests/vectors.rs`. The repository label, numeric ID, PR and head are synthetic and never resolved or contacted. Fixed timestamps demonstrate a 120-second difference, not current validity. Never use these values as live defaults or import them as trusted registry state.

`fixtures/candidate-expected.json` records literal canonical payload and operation as JSON strings, plus hexadecimal hashes and the base64url mandate challenge. Decode each JSON string and encode it as UTF-8 to obtain the exact expected bytes. File indentation and final newlines are not part of those strings or digest inputs. The hash input is the documented UTF-8 domain, one terminal NUL byte, then canonical bytes; nonce appears inside the payload, not appended separately.

Expected strings were constructed with manually ordered ASCII members in Node, serialized with native `JSON.stringify`, and hashed with `node:crypto`. All five expected byte/hash fields were independently reproduced with the pinned Node 24.21.0 runtime. Rust independently compares `serde_jcs` output and OpenSSL SHA-256 against the recorded literals. This is independent serialization and digest calculation, not a second cryptographic-provider claim or a general JCS conformance suite. No fixture-generation function shared with the Rust serializer supplies expected values during tests.

Five tests cover exact bytes/digests, source key-order and whitespace equivalence, mutations to all 20 scalar fields, operation-versus-authority coverage, and domain/NUL distinctions. A recursive scalar-path inventory must match the mutation list, so an added fixture leaf cannot silently escape coverage. Some mutations intentionally violate the candidate schema: those tests establish digest sensitivity, not parser rejection. Input uses ordinary serde_json only because it is trusted fixed fixture data; its duplicate collapse remains unsuitable for production mandate parsing.

Run `python3 scripts/check-canonicalization.py` from repository root. Existing CI picks up the new integration test automatically. Evidence signatures, issuer envelopes, agent execution proofs, authoritative registry checks, time enforcement and complete negative schema vectors belong to subsequent reviewed slices. Signed native storage and all remaining P06 acceptance gates stay open.
